# 源码整理：职责与状态归属

## 范围与边界

用户先选择Palm源码后明确纠正为“忘了Palm Compass，整理本项目源码”。本轮只改Compass Navigation Overhaul项目，不改第三方Palm源码或安装文件。整理以保持行为为目标，不混入启停开关、跨存档配置持久化、独立任务UI迁移，也不删内嵌模式和已验证的共享HUD边界。

此次完成**源码体量扫描和热点抽查，以及第一批重构**，不是全仓代码已全面清理。已有未提交的原型和文档全部保留；未暂存、提交或部署。重构后构建出的安装包包含新DLL，但MO2中的DLL仍为之前部署的版本。

## 审查与优先级

| 模块 | 观察到的问题/风险 | 本轮处理 |
|---|---|---|
| `source/palmtest/PalmTest.cpp` | 配置IO、场景遍历、模型加载、状态/调度混在一起，多组文件级可变状态 | 优先拆分并明确资源所有权 |
| `tools/palmtest/CMakeLists.txt` | 只跑变换测试也必须先提供/编译大型nifly工具 | 解耦独立测试与可选网格生成器 |
| `source/settings/Dispatch.cpp` | 大量重复键分发，混用单行/多行格式；各键分组、类型和边界并不相同 | 后续先建立完整键/类型/钳制契约，再评估表驱动；本轮不改 |
| `source/hud/SceneNodes.cpp` 与掌上节点查询 | 看似重复“找罗盘”，但前者通用HUD查找和新原型的路径验证/唯一候选策略不同 | 不盲目合并；后续先明确调用方契约 |
| `source/ui/SettingsLifecycle.cpp` | 设置应用同时承担GFx能力检查及诊断输出 | 后续评估拆分诊断，但保留初始化/热重载顺序 |
| `source/RE/G/GFxValue.cpp` | 文件长，但主要是底层接口实现，涉及类型/ABI | 不因行数多就重写或机械拆分；须有明确维护收益及接口验证再动 |

“更少行数”不是验收标准。本次增加私有接口和测试会增加总行数，目的是把配置、资源和调度的修改边界分开，而不是制造大量无职责的小文件。

## 首批结构

| 文件 | 职责及状态 |
|---|---|
| `PalmTest.h/.cpp` | 对外仍只有SKSE消息入口；内部Runtime拥有配置快照、罗盘引用、生命周期原子标记与计时器 |
| `Config.h/.cpp` | 只读INI，保留键、默认值、范围、截断缓冲长度；不负责轮询，不写用户设置 |
| `ConfigValue.h` | 无引擎依赖的原有浮点解析逻辑，供正式代码及原生测试共用 |
| `Scene.h/.cpp` | 无持有状态、无场景写操作；负责候选查询、祖先/当前场景检查、可见性与有限值检查 |
| `Surface.h/.cpp` | 只持有本项目面板和宿主节点，负责加载失败状态、重试、隐藏、解绑和独立世界变换更新 |
| `Pose.h` | 原有尺寸隔离/坐标转换模板不变 |
| `HiggsInterface001.h/.cpp` | 第三方API适配不变，许可证不变 |

原PalmTest.cpp从251行调整为153行；原每帧长流程变成重置、轮询配置、验证场景、寻找锚点和更新表面的调度入口。隐藏、解绑、模型加载失败重试由Surface统一负责；Runtime解绑时仍同时清除锚点和搜索计时。

## 保持的契约

- 原型默认关闭；INI每秒读取；缺失或歧义候选每秒重试，日志仍按原策略去重。
- HIGGS注册时机仍为PostPostLoad，保持在Palm公开实现PostLoad注册之后。
- 读档/新游戏消息只发起状态请求，帧回调处理重置；加载期间先隐藏，不使用旧场景。
- 节点搜索、可见性和有限值检查共6个函数体仅移动，去除空白后与重构前逐一比对一致。
- 保留旧解析语义，包括纯空白输入在原解析函数中经过空白跳过后按0钳制的边缘行为；本轮没有将其顺手修成另一套规则。Windows INI读取层的空白处理需另行验证，不能仅凭纯函数测试断言用户配置故障。
- 配置刷新改为一次读取快照后应用；保持同帧结果与开关切换动作，不声称机器指令或每次IO与日志的微观顺序完全相同。
- 原Compass/QuestList的SWF、模型纹理、MCM键、目标排序与760～960候选带均未修改。

## 验证结果与限制

- 完整`build.bat`编译、链接、SWF哈希、主包18/中文1文件及ZIP校验通过。
- CTest 3/3：288组真实Pose模板用例、23组真实配置解析用例、14组真实Scene查询代码用例。
- Scene测试编译正式`Scene.cpp`，但使用测试专用场景替身；正式DLL的构建配置不包含该替身目录。它验证查询算法，不验证引擎ABI/真实渲染。
- 既有AS2反编译模拟56/56、Python24/24通过。
- 114个安装/配置文件哈希不变；没有自动替换MO2中的DLL或重新启用Palm。
- 没有本轮VR验收，也没有用这些测试覆盖全部Runtime回调并发/读档生命周期；实际效果仍须在获准部署后实测。
- 临时基线、构建与测试日志保存在已忽略的`build/source-cleanup/`，不进入提交。

## 测试入口

在已有C++编译环境中，不需要nifly也能运行：

```text
cmake -S tools/palmtest -B build/palmtest-unit
cmake --build build/palmtest-unit --config Release
ctest --test-dir build/palmtest-unit -C Release --output-on-failure
```

如需原来的网格生成器，使用独立构建目录并继续传入`-DNIFLY_SOURCE_DIR=<外部源码目录>`；未传入时只构建测试，不将其视为报错。

## 后续整理约束

1. 优先补齐设置分发的逐键行为测试，再减少重复逻辑；特别注意替换min/max表达式可能改变NaN处理。
2. 场景查询统一前先区分普通HUD与Palm原型的候选选择、缓存失效和可见性定义，不以函数名相似认定等价。
3. 不在重构中恢复旧UV补偿、删除旧模式或混入独立任务UI新功能。
4. 每批独立编译、回归和审阅，部署/提交另按用户授权执行。
